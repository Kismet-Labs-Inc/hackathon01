Replace the placeholder `app/scan.tsx` with the full scan screen implementation. This is a single large file (~300-400 lines) with multiple states managed by a state machine pattern.

**Screen states:** `'camera' | 'preview' | 'processing' | 'success'`

**STATE: camera** (default)
- Full-screen `CameraView` from expo-camera with `facing="back"` and `ref={cameraRef}`. Full-bleed: `colors.bg` background, no status bar chrome, no header (per DESIGN.md layout rules)
- Use `useCameraPermissions()` hook. If not granted, show permission request UI on `colors.bg` background:
  - Heading: "Camera Access" — Bold (700), 28px, `colors.white`, centered
  - Body: "We need camera access to scan menus" — Regular (400), 16px, `colors.gray`
  - "Allow Camera" button: pill-shaped (`borderRadius.full`), `colors.coral` bg, white bold text, full-width, 16px vertical padding (Primary CTA per DESIGN.md)
  - "Use Gallery Instead" link below: Regular (400), 14px, `colors.coral` text, no background
- Subtle rounded rectangle framing guide overlay (View with transparent center, semi-transparent `colors.bg` at 0.6 opacity on edges) with "Position the menu within the frame" hint text below center — Regular (400), 14px, `colors.gray`
- Large circular capture button centered at bottom: 70x70, `borderRadius.full`, `colors.coral` background, Pressable with reanimated scale feedback (0.9 on press). Ring: 78x78 outer ring, `rgba(232,116,74,0.3)` border, 3px width
- Small "Gallery" text button in bottom-left corner — Medium (500), 14px, `colors.white` — calls `ImagePicker.launchImageLibraryAsync({ mediaTypes: 'images', quality: 0.6, base64: true })`
- BackButton in top-left for navigation back (floating overlay per DESIGN.md navigation pattern)
- On capture: call `cameraRef.current.takePictureAsync({ quality: 0.5, base64: true })`, transition to 'preview'
- On gallery pick: if not canceled, transition to 'preview' with picked image
- Screen padding: `spacing.lg` (24px) horizontal on overlay elements

**STATE: preview**
- Show captured/picked photo as full-screen Image (using photo.uri), `colors.bg` behind it
- Two buttons at bottom in a row, horizontal, `spacing.lg` padding, `spacing.md` gap between them:
  - "Retake": pill-shaped (`borderRadius.full`), transparent bg with 1px `colors.coral` border, `colors.coral` text, Semi-Bold (600) — Secondary CTA per DESIGN.md
  - "Use This": pill-shaped (`borderRadius.full`), `colors.coral` bg, `colors.white` text, Bold (700) — Primary CTA per DESIGN.md
  - Both buttons: equal flex, 16px vertical padding
- "Use This" action: transition to 'processing', call `store.setProcessing(true)`, then `parseMenuPhoto(photo.base64, GEMINI_API_KEY)`
  - On success: call `store.setItems(items)`, transition to 'success'
  - On error: this shouldn't happen since menuParser falls back to cached data, but if it does: `store.setError(message)`, show brief error then transition to 'success' with fallback data

**STATE: processing**
- Show the captured photo as background (same Image)
- Semi-transparent dark overlay: `colors.bg` at 0.7 opacity
- Animated scan line using react-native-reanimated: a solid `colors.coral` View, 3px tall, full width, 0.8 opacity — sweeps vertically using `withRepeat(withTiming(imageHeight, { duration: 2000, easing: Easing.linear }), -1, true)`. No LinearGradient — keep it simple.
- "Scanning menu..." text centered: Semi-Bold (600), 18px, `colors.white`, with subtle reanimated opacity pulse (0.5 to 1.0, 1s loop)
- No cancel button -- processing is fast (or falls back quickly on timeout)

**STATE: success**
- Same photo background with dark overlay (`colors.bg` at 0.7 opacity)
- Animated count-up centered vertically and horizontally:
  - Number: Extra Bold (800), 48px, `colors.white` — animates from 0 to `store.items.length`
  - "dishes found!" label below: Semi-Bold (600), 20px, `colors.coral`
  - Use reanimated `useAnimatedProps` with `Animated.createAnimatedComponent(TextInput)` pattern from RESEARCH.md
- Count-up duration: ~1000ms
- After count-up completes (~1.5s total including pause), auto-advance: `router.push('/mood')`
- Use setTimeout for the auto-advance delay (1500ms after entering success state)

**Hidden dev toggle:** Wrap the BackButton or a specific area with an `onPress` counter. On 3 rapid taps (within 1 second), call `toggleForceFallback()` and show a brief "Dev: Fallback mode toggled" text that fades out. This gives the demo safety net per locked decision.

- All text uses Plus Jakarta Sans (loaded project-wide). Reference DESIGN.md Section 3 for weight/size per element type
